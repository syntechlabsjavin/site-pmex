# PMEX content and design requirements

Apply these requirements to every page and future edit. They supersede old reference copy and earlier styling instructions...

## Single stylesheet: dist/css/root.css (supersedes every rule below that names another CSS file)

- Every page loads exactly one stylesheet: `<link rel="stylesheet" href="/css/root.css"/>`. There is no style.css, no other file in dist/css and no inline `<style>` block. Do not add any.
- Temporary exception: the old homepage (dist/index.html) also loads `/css/legacy-home.css`, after root.css. It holds the homepage-only blocks (home-responsive, home-neutral and the homepage's inline-* blocks) because the homepage will be rebuilt on the design system. Do not add rules to it and do not load it anywhere else. When the new homepage is live, delete the file and its `<link>`. `npm run check:css` enforces both.
- root.css holds, in order: the THEME block (`--theme-*`, the only place where a color value is written), the legacy color variables `--c-HEX` generated from it, the design tokens (`--grad-*`, `--shadow-*`, `--transition-*`, `--lift-hover`), the `.c-HEX` / `.bg-c-HEX` / `.bdr-c-HEX` classes, then one block per former stylesheet or inline style block.
- Site-wide color change: edit the value in the THEME block of root.css, then run `npm run theme:build`. Every shade, tint, transparent variant, shadow and gradient follows. `--c-HEX` lines are generated by scripts/build/build-theme-tokens.js; never edit them by hand (their names are legacy labels, not their current value).
- Every gradient names its color space (`linear-gradient(to right in srgb, ...)`), so the blend does not change with color notation. Run `npm run gradients:check` after adding one (`npm run gradients:pin` fixes it).
- Before committing a CSS change run `npm run check:regression` (pixel and computed-style diff of every page against the tag `css-baseline`; pages can be passed as arguments).
- Every rule of those blocks starts with `[data-css~="name"]`. A page lists the blocks it uses in `<html data-css="...">`, in the same order it used to load them. A new page copies the `data-css` value of a sibling page of the same family. New styles go into the matching block of root.css (or a new block with a new name plus a `data-css` entry), never into a new file.
- No color literal anywhere (root.css declarations, `style=""` attributes, page scripts). New CSS writes the semantic token: `var(--theme-primary)`, `var(--theme-text)`, `var(--theme-border)` ...; a transparent variant is `rgb(from var(--theme-primary) r g b / 15%)`. Existing `var(--c-HEX)` references keep working. A color that is not a theme token yet is added once to the THEME block first. The only exceptions are `@property` initial values and class names such as `bg-[#AAD39C]`.
- Where older rules below say "site-buttons.css", "reference-typography.css", "specialty-site-palette.css" and so on, they now mean the block of root.css with that name (`[data-css~="site-buttons"]`, `[data-css~="reference-typography"]`, ...). The block order in root.css already keeps site-buttons first and reference-typography second.
- No Tailwind: the site has no Tailwind build, block or package (removed 2026-11-11, plan: docs/DESIGN-SYSTEM-PLAN.md). Never add Tailwind classes to a page or script. The reset is the `[data-css]` reset block; custom rules of the old style.css are block `style`. New markup uses the design-system classes of `@layer ds` at the end of root.css: text roles `t-*`, `fw-*`, `lh-*`, spacing `mt-*/mb-*/gap-*`, layout `row/stack/grid-3`, components `card`, `panel`, `chip`, `icon`, `section-head` ...; add a missing component there, with theme tokens. The `u-*` classes (generated section of the ds layer) are the former one-off utilities: reuse them only when no component fits, and prefer replacing groups of them with a component.

Pages live in category folders under `dist/` and every link uses root-absolute paths (`/css/root.css`, `/specialties/cardiology.html`). Scripts are split into `scripts/build`, `scripts/checks` and `scripts/archive`. See README.md.
